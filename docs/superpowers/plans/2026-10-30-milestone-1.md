# Queryfirst Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `qf` (Postgres + TypeScript): `generate`, `check`, `test`, `bundle`, `schema`, `init --from-pgtyped`. It must be a drop-in replacement for pgtyped in simplyfirst-app, distributed on npm as `queryfirst`.

**Architecture:** A Rust cargo workspace. `qf-sqlfile` handles query files, annotations and the pgtyped-compatible param lexer and IR. `qf-meta` owns the meta model, hashing and diffing. `qf-pg` handles describing, the catalog, and the nullability and param analyzers. `qf-gen-ts` is the TypeScript generator; type rendering is kept separate from the pgtyped runtime binding. `queryfirst` is the CLI binary `qf`, which orchestrates everything and owns all file writes. Generators are pure functions from meta to files, and only `qf-pg` touches a database.

**Tech Stack:** Rust (stable, pinned in `rust-toolchain.toml`), tokio, tokio-postgres + rustls, pg_query (pganalyze, libpg_query), clap, serde/serde_json, sha2, globset + walkdir, strsim, assert_cmd. A small TypeScript package `queryfirst-runtime` (built with tsc, tested with vitest). npm per-platform binary packages.

**Spec:** `docs/superpowers/specs/2026-10-30-queryfirst-design.md`. Read it before any task. Section numbers below (§n) refer to it.

**Reference implementation for drop-in compatibility:** pgtyped source at `c:\dev\pgtyped` (cli 2.3.0, as used by simplyfirst-app). These are the authority on output bytes:
- `packages/cli/src/generator.ts`: file layout, interface rendering, field sorting, `never` on error
- `packages/cli/src/types.ts`: `DefaultTypeMapping`, `TypeAllocator`, helper types, enum unions, import declaration
- `packages/parser/src/loader/sql/` (grammar `SQLLexer.g4`, `SQLParser.g4`; `index.ts` `queryASTToIR`): annotation and param syntax, IR
- `packages/runtime/src/preprocessor-sql.ts`: how the runtime consumes the IR (transform types, locs)

**First consumer:** `c:\dev\simplyfirst-app`. 843 `.psql` files, 943 queries; the 26 files with more than one query are listed by `git ls-files '*.psql' | xargs grep -c "@name" | grep -v ":1$"`. The config is `pgtyped-config.json` / `.pgtyped.ts`, and the `pg` type parsers live in `next.config.js`.

## Global Constraints

- Branding: "Queryfirst", always with a small f, in all docs, messages and help text. npm package `queryfirst`; binary `qf`; config `queryfirst.json`; meta file `<stem>.qf.json` next to the source; manifest `queryfirst.manifest.json`.
- Runtime npm package: `queryfirst-runtime` (unscoped; the `@queryfirst` scope is unverified).
- Every file the tool writes uses LF line endings and ends with a trailing newline. A file is written only if its bytes would change.
- Source text is normalised (CRLF → LF) as soon as it is read, before hashing, lexing, IR or describing. Nothing the tool emits may depend on the checkout's line endings.
- Meta files contain nothing environment-specific: no OIDs, no database name, host, port or server version. Types are referenced by name.
- Columns are matched by name, never by position (in test, and in the generated readers).
- Nothing is ever executed against a database. Use prepare/describe and catalog `SELECT`s only.
- Connection strings are never logged and never written to disk.
- No interactive prompts. No spinners unless stdout is a TTY.
- Exit codes: `0` ok; `1` query, check or test errors; `2` usage, config or connection errors.
- Diagnostic text format: `path:line:col: error[QFnnn]: message`, optionally followed by `  hint: …`. Severities are `error`, `warning` and `note`. Paths are relative to the project root and use `/`.
- `--json` on every command prints a single JSON document on stdout (shape defined in Task 12). Human-readable diagnostics go to stderr; the summary line goes to stderr too.
- Diagnostic codes (fixed here so every task uses the same ones):

| Code | Meaning |
|---|---|
| QF001 | Annotation/header syntax error |
| QF002 | More than one query in a file |
| QF003 | `@name` disagrees with file name (warning) |
| QF004 | `@type` / `!` / `?` refers to an unknown column or param |
| QF010 | Postgres rejected the statement (prepare error) |
| QF011 | Postgres could not determine a parameter type (hint: cast `:p::type`) |
| QF012 | Two result columns with the same name (hint: alias one) |
| QF013 | Anonymous result column `?column?` (hint: alias it) |
| QF014 | Unsupported Postgres type (no mapping) |
| QF020 | Nullability analyzer gave up on a column (note) |
| QF030 | `.sql` changed since meta was generated (stale) |
| QF031 | Generated file edited by hand or missing |
| QF032 | Generated file doesn't match its meta (different qf version) |
| QF033 | Meta records a broken query |
| QF034 | Source has no meta file |
| QF035 | Meta file has no source (orphan) |
| QF040 | test: expected column missing |
| QF041 | test: column type changed |
| QF042 | test: column became nullable |
| QF043 | test: extra column (note) |
| QF044 | test: column became non-null (note) |
| QF045 | test: parameter added/removed/type changed |
| QF046 | test: query fails to prepare on target |
| QF047 | test: enum lost values (error) / gained values (warning) |
| QF048 | test: DB timezone ≠ UTC while `timestamp: "utc"` |
| QF049 | test: query was recorded broken at generate time |
| QF090 | Cannot reach database (exit 2) |
| QF091 | Config error (exit 2) |

## Review Focus

1. **The connection drops mid-run, or the tunnel closes.** Expected: `generate` aborts with QF090 and exit 2, and **writes nothing**. A connection error must never be recorded as "broken query" in hundreds of meta files. Test in Task 12.
2. **CRLF working copies** (simplyfirst has `core.autocrlf=true`, so every `.psql` is CRLF on Windows). Expected: the meta, IR, hashes and wrappers are byte-identical to an LF checkout. Tests in Task 3 and Task 12.
3. **Non-ASCII SQL** (French accents in string literals and comments). Expected: IR `locs` are in UTF-16 code units, as pgtyped computes them in JS. Postgres error `position` (counted in characters) maps to the correct line:col. Tests in Task 3 and Task 6.
4. **Next.js route paths with `[id]` and `(queries)`.** Expected: paths given on the command line are taken literally, never interpreted as globs. Emitted paths use `/`. Tests in Task 12.
5. **Interface field order.** pgtyped sorts fields with JS `localeCompare` (ICU root collation), not byte order. For example `accountId`, `Address`, `address_line`, `id2` must come out in the same order pgtyped produces. Test in Task 9.
